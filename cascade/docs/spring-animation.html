    Spring animation in UI Toolkit

    Unity UI Toolkit has no spring animation built in. USS transitions and the experimental animation API only offer fixed-duration easing curves. You can write a small spring yourself on the panel scheduler, or use a library: Cascade Pro adds a spring to any animation in one call.

    A spring moves an element toward its target like a physical object: it speeds up, can overshoot, and settles. Its length comes from its stiffness rather than a fixed duration. The real reason to use one is interruption. When a new target arrives halfway, a spring keeps its current speed and turns toward the new target. An eased tween has to start again from zero speed, which shows as a hitch. Anything the player can click rapidly, drag or toggle looks better on a spring.

    Without a library: a spring on the scheduler

    Every VisualElement has a scheduler that can run code each frame. A damped spring is a few lines of math on top of it:

    using UnityEngine;
using UnityEngine.UIElements;

public static class SimpleSpring
{
    // Springs el's horizontal position to targetX. Each call starts again from zero speed.
    public static IVisualElementScheduledItem SpringToX(VisualElement el, float targetX,
                                                        float stiffness = 300f, float damping = 22f)
    {
        float x = el.resolvedStyle.translate.x, velocity = 0f;
        IVisualElementScheduledItem tick = null;
        tick = el.schedule.Execute(() =>
        {
            float dt = Mathf.Min(Time.unscaledDeltaTime, 1f / 30f);   // keep a frame hitch from exploding it
            velocity += (stiffness * (targetX - x) - damping * velocity) * dt;
            x += velocity * dt;
            el.style.translate = new Translate(x, 0);
            if (Mathf.Abs(targetX - x) < 0.01f && Mathf.Abs(velocity) < 0.01f)
            {
                el.style.translate = new Translate(targetX, 0);
                tick.Pause();                                          // settled
            }
        }).Every(0);
        return tick;
    }
}

    This is fine for one property and one target. It gets harder from there:

    • It starts from zero speed on every call, so a quick second click shows the hitch a spring is meant to remove. Keeping the speed means storing it per element and pausing the previous run.
    • Scale, rotation, colour and size each need their own version.
    • Nothing stops it when the element leaves the panel, and two runs on the same element fight each other.
    • Stiffness and damping are hard to tune by eye.

    With Cascade: a spring on any verb Pro

    using Cascade;

card.Animate().ScaleTo(1.2f, 0f).Spring(SpringPreset.Bouncy);
panel.Animate().MoveY(0f, 0f).From(40f).Spring(SpringPreset.Snappy);

    Spring() replaces the verb's duration: the spring decides how long it takes, so pass 0f as the duration.

    PresetFeelUse for
    SpringPreset.Gentleslow, smooth, no visible bouncelarge panels, backgrounds
    SpringPreset.Snappyquick, settles fastbuttons, menus, most UI
    SpringPreset.Bouncyovershoots and wobblesrewards, playful buttons, game UI

    A custom spring, described by feel

    Tuning stiffness and damping by hand is slow. SpringConfig.FromResponse takes two numbers that match what you see:

    // response: roughly how long one swing takes, in seconds (0.15 = a quick control, 0.5 = a large panel)
// bounce:   0 = no overshoot, toward 1 = very bouncy
var drawer = SpringConfig.FromResponse(0.4f, 0.15f);
sidePanel.Animate().MoveX(0f, 0f).Spring(drawer);

    If you already know the physics values, use new SpringConfig(stiffness, damping, mass).

    Interruptions that keep momentum

    // Call this on every click. No StopAnimations() first, on purpose.
void Flip()
{
    _flip = !_flip;
    card.Animate().MoveX(_flip ? 90f : -90f, 0f).Spring(SpringPreset.Bouncy);
}

    Click quickly and the card turns around smoothly instead of stopping dead each time. The animation that is replaced hands its current velocity to the new one. Call StopAnimations() first only when you want a hard reset, because it drops the velocity too.

    Springs on hover and press

    playButton.OnHover().ScaleTo(1.12f, 0f).WithSpring(SpringPreset.Bouncy);
playButton.OnPress().ScaleTo(0.94f, 0.08f);

    Moving the pointer on and off quickly keeps the motion continuous, for the same reason as above.

    Springs in a sequence

    card.Animate()
    .MoveY(-40f, 0.3f).Ease(Ease.OutCubic)
    .Then().ScaleTo(1.1f, 0f).Spring(SpringPreset.Bouncy)
    .Then().MoveY(0f, 0f).Spring(SpringPreset.Snappy);

    A spring step ends when the spring has settled, then the next step starts.

    When not to use a spring

    • Exact timing: a progress bar or something synced to audio needs a fixed duration. Use an ease.
    • Fades: opacity has nothing to overshoot. An ease reads cleaner.
    • Exits: things leaving the screen usually look better accelerating away with Ease.InCubic.
