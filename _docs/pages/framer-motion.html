Coming from Framer Motion

UI Toolkit borrowed CSS from the web, and Cascade borrows its animation model from Framer Motion. If you know one, here is the other.

A button, ported

// Framer Motion
<motion.button
  initial={{ opacity: 0, y: 24 }}
  animate={{ opacity: 1, y: 0 }}
  whileHover={{ scale: 1.05 }}
  whileTap={{ scale: 0.96 }}
  transition={{ type: "spring", stiffness: 210, damping: 22 }} />
// Cascade
button.OnHover().ScaleTo(1.05f, 0.15f, Ease.OutBack);
button.OnPress().ScaleTo(0.96f, 0.08f);
button.Animate()
      .Fade(1f, 0f).From(0f).Spring(SpringPreset.Snappy)
      .MoveY(0f, 0f).From(24f).Spring(SpringPreset.Snappy);

Differences worth knowing

  • Durations are seconds, like Framer Motion, not milliseconds like Unity's own scheduler.
  • Verbs in one chain run together. .Then() starts the next step, where Framer Motion would use keyframes or a sequence.
  • Animations stop when the element leaves the panel, the way Framer Motion stops on unmount.
  • There is no layout animation (FLIP). The Width, Height, Top and Left verbs animate layout values directly.
